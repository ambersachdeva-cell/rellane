# R24 native inventory receipt — 24 September 2026

Apple Command Line Tools are present: `xcrun --find clang` resolved to `/Library/Developer/CommandLineTools/usr/bin/clang`; Apple clang reports version 17.0.0 on arm64 Darwin. The standalone `inventory.c` compiled with the release command in [README.md](README.md), without installing a dependency.

On synthetic temp trees only, the helper emitted the same sorted, hex-path SHA-256 manifest twice. It accepted a symlinked ancestor alias while rejecting a symlinked root leaf, symlink and hard-link entries, a sparse file over 64 MiB, and a tree beyond 32 levels. Its test-only pause between `fstatat` and `openat` allowed a nested directory to be swapped for an outside symlink; `openat(O_NOFOLLOW)` refused the replacement, the process emitted no manifest, and the outside fixture remained unchanged. The native suite skips on non-macOS hosts or hosts without `xcrun`. Focused native/recovery/ownership tests: **24/24 passed** on this Mac. Desktop TypeScript typecheck passed.

Earlier synthetic Node 24.14.1/macOS probes showed `fs.readdir('/dev/fd/<directory-fd>')` returns `ENOTDIR`, while Node's `fs.readdir` and `fs.opendir` do not accept a directory `FileHandle`. In a separate synthetic SQLite probe, both `sqlite.backup(db, '/dev/fd/<preopened-file-fd>')` and `VACUUM INTO '/dev/fd/<preopened-file-fd>'` returned `ERR_SQLITE_ERROR` because SQLite could not open that target. [Node's SQLite API](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html) explicitly says its backup path overwrites an existing file. [SQLite's online backup API](https://www.sqlite.org/backup.html) and [`VACUUM INTO`](https://www.sqlite.org/lang_vacuum.html) provide a consistent Book snapshot through a trusted open connection, but neither makes a raw copied tree coherent.

**Boundary:** this helper proves descriptor-contained traversal from the opened canonical root for one observation. The caller must separately attest canonical source identity and intended boundary; the helper does not establish an immutable or quiescent whole-root snapshot. It hashes file payload bytes and does not claim a metadata-only export. It does not classify stores, handle WAL or keys, package bytes, import, or publish. Whole-data recovery remains blocked on an attested quiescent snapshot or writer-freeze contract; a trusted WAL-aware Book receipt; a complete owned-store and key-portability policy; and a no-overwrite staged import with rollback and reopen tests. No owner data, Keychain item, migration, app installation, or destination data was touched.
